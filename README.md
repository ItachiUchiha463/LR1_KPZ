# Автоматизована система моніторингу та інтелектуальної діагностики

Продукційна експертна система: приймає показники моніторингу через REST API,
проганяє через 125 правил ЯКЩО-ТО в 4 шари виводу, повертає діагноз(и)
і рівень критичності. База знань зберігається в MongoDB, керування нею —
через власний CRUD API (Swagger UI на `/docs`), окремого візуального
редактора немає.

## Структура

```
des/
├── backend/                    REST API (FastAPI) над MongoDB
│   ├── main.py                  точка входу
│   ├── config.py                 читання .env
│   ├── db.py                     підключення до MongoDB (Atlas / локально)
│   ├── kb_service.py             збірка бази знань із 2 колекцій + кеш
│   ├── schemas.py                Pydantic-валідація
│   ├── seed_kb.py                одноразовий імпорт data/knowledge_base.json
│   ├── requirements.txt
│   ├── .env.example
│   └── routers/
│       ├── rules.py              CRUD правил
│       ├── facts.py              CRUD опису фактів
│       ├── diagnose.py           POST /api/diagnose - запуск діагностики
│       ├── runs.py               історія збережених прогонів
│       ├── kb.py                 /api/kb/validate - статична перевірка
│       └── health.py             /api/health, /api/stats
│
├── data/
│   ├── gen_kb.py                 генератор бази знань, частина 1 (RAM/CPU/Диск)
│   ├── gen_kb_part2.py           частина 2 (Мережа/БД/Каскади/СППР)
│   └── knowledge_base.json       згенерований файл: 125 правил, 70 фактів
│
├── inference_engine/             МАШИНА ВИВОДУ (чистий Python, без залежностей)
│   ├── working_memory.py         робоча пам'ять: single / collect / max

```

## Ключове архітектурне рішення

Умови правил зберігаються **структуровано**, не текстом:

```json
{"fact": "доступна_памʼять_%", "op": "<", "value": 15}
{"fact": "load_average_1хв", "op": ">", "ref_fact": "nproc", "factor": 1.5}
```

Читабельний рядок ЯКЩО-ТО (поле `text`) генерується зі структури автоматично
і використовується лише для показу та звіту — машина виводу читає саме
структуровані поля.

## Запуск з нуля

### 1. MongoDB

Локально або через **MongoDB Atlas** (хмара). Для Atlas: `Database →
Connect → Drivers → Python` — скопіювати рядок підключення, і обов'язково
`Network Access → Add IP Address`.

### 2. Залежності

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Налаштування з'єднання

```bash
cp .env.example .env
```

Вставити реальний `MONGO_URI` в `.env`.

### 4. Імпорт бази знань

```bash
python seed_kb.py
```

### 5. Запуск бекенда

**З папки `backend/`**, не з кореня проєкту:

```bash
uvicorn main:app --reload --port 8000
```

Перевірка: [http://localhost:8000/api/health](http://localhost:8000/api/health)
Документація й керування правилами: [http://localhost:8000/docs](http://localhost:8000/docs)

## Керування базою знань

Окремого візуального редактора немає — усе керування (додати/змінити/видалити
правило чи факт) робиться через автоматично згенеровану Swagger-документацію
на `/docs`: там є кнопка "Try it out" для кожного ендпоінта, включно з
повноцінним CRUD для `rules` і `facts`.

## Тести

```bash
python -m tests.test_engine
```

43 перевірки: статична валідація бази знань, "здорова" система, критичні
сценарії, кілька одночасних діагнозів, міжгрупові правила, пояснюваність
(`engine.explain()`), ескалація рівня за тривалістю, стійкість до
некоректних вхідних даних, детермінованість.

## Свідомо спрощено в цій версії

- **Нейромережа прибрана.** Правило Діаг-16 (розрізнення DDoS проти
  легітимного піку трафіку) повернено до однофакторної версії
  (`патерн_трафіку = "аномальний_сплеск"` → підозра на DDoS без уточнення) —
  задокументовано в примітці правила як свідоме обмеження. Гібридна
  архітектура (нейронний вузол + `inference_engine.engine.neural_runner`)
  лишається архітектурно підтримуваною, якщо колись знадобиться повернути.
- **Візуального редактора немає.** CRUD через `/docs` цілком закриває
  потребу редагувати базу знань вручну під час лабораторної.
- Свідомі обмеження каскадної гілки та безпекових критеріїв — див.
  попереднє обговорення в звіті методички.


## Оболонка інтерфейсу та довідкова система (практична робота №2)

Запуск: `cd backend && py -m uvicorn main:app --port 8000`, потім відкрийте `app.html` у браузері.
Оболонка містить верхнє меню, рядок стану, контекстні меню й гарячі клавіші (F1, Ctrl+1/2/3, F5, Esc).
Три сторінки (`diagnose.html`, `logs.html`, `editor.html`) працюють і окремо.

Довідка (інструкція користувача) зроблена на Docsify (`help/src/`): 6 тем у Markdown, зміст —
`_sidebar.md`, точка входу — `index.html`. Компіляції не потребує: Docsify читає `.md`-файли
напряму в браузері. Запуск: `python help/serve_manual.py` (потрібен інтернет для CDN), потім
пункт меню «Довідка» в `app.html` (чи клавіша F1) відкриває сайт новою вкладкою.

UI-тести у Chromium: `pip install playwright`, `playwright install chromium`, `python tests/ui/run_ui_tests.py`
(перевіряє і оболонку, і сайт інструкції - `serve_manual.py` тест піднімає сам).
Звіт і графічна модель інтерфейсу — у `docs/pr2/`.
