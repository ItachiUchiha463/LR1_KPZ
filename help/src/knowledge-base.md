# База знань

## Із чого складається база знань

База знань має три частини, що редагуються на окремих вкладках редактора:

| Частина | Що це | Приклад |
|---|---|---|
| **Факти** | Показники й проміжні стани, про які «знає» система | `доступна_памʼять_%`, `тиск_на_памʼять` |
| **Правила** | Логіка «ЯКЩО умови ТО висновок» | Якщо памʼяті менше 15 % і є swap — тиск на памʼять критичний |
| **Діагнози** | Довідник висновків: назва, критичність, опис, рекомендація | «Критичний витік памʼяті» |

Правила виконуються **шарами**: правила шару 1 обчислюють проміжні стани з вхідних показників, правила шару 2 і вище роблять із проміжних станів діагнози ([Шар виводу](reference.md)).

Після кожної зміни корисно виконати Перевірку бази знань.


## Правила

Вкладка **Правила** показує список усіх правил (ідентифікатор, гілка, шар, тип). Клік по правилу відкриває форму праворуч.

Поля форми:

| Поле | Значення |
|---|---|
| ID, Гілка, Шар | Ідентифікація правила й порядок виконання |
| Тип правила | Проміжне або діагностичне |
| Впевненість (CF) | Число від 0 до 1 |
| Умови | Один чи кілька рядків, з'єднаних через «І» |
| Висновки або Діагноз | Що встановлює правило |
| Читабельний текст | Формується автоматично й оновлюється під час редагування |

Правило можна вимкнути, не видаляючи (прапорець «увімкнено» або контекстне меню). Створення нового: кнопка **+ Створити**.

![Форма правила](img/shell-editor-rule.png)

Змінити, вимкнути чи видалити правило: [інструкція](howto.md).

Покрокові приклади: [діагностичне правило](howto.md), [правило на два шари](howto.md).

## Проміжне і діагностичне правило

**Проміжне правило** виводить *стан* із показників. Висновок — пара «факт = значення».

> ЯКЩО `доступна_памʼять_%` < 15 І `кількість_swap_операцій` > 0 ТО `тиск_на_памʼять` = «критичний»

**Діагностичне правило** ставить *діагноз*. Замість пари «факт = значення» ви обираєте готовий діагноз зі списку довідника. Критичність діагнозу правило не задає — вона береться з довідника.

> ЯКЩО `тиск_на_памʼять` = «критичний» І `тренд_памʼяті` = «підозра_на_витік» ТО діагноз «Критичний витік памʼяті»

Тип обирається у списку **Тип правила**; від нього залежить, що показується в блоці висновків: конструктор висновків чи список діагнозів.

## Умови й оператори

Умова — це рядок із полів: **факт → оператор → з чим порівнювати → значення**. Усі умови правила з'єднані через «І»: правило спрацьовує, лише коли виконано кожну.

Кнопка **+ додати умову** додає рядок, **×** — видаляє.

### Оператори

| Оператор | Значення | Що вводити |
|---|---|---|
| `<`  `≤`  `>`  `≥` | числове порівняння | число або інший факт |
| `=`  `≠` | дорівнює / не дорівнює | значення |
| `серед` / `не серед` | значення входить у список | значення через кому |
| `= true` / `= false` | логічний факт | нічого |
| `містить` | факт-список містить значення | значення |

### Порівняння з іншим фактом

У полі **з чим** оберіть «інший факт» і вкажіть множник. Так записується, наприклад, «завантаження системи більше за кількість ядер × 1,5»: факт `load_average_1хв`, оператор `>`, з чим — інший факт `nproc`, множник `1.5`.

Поле значення підлаштовується під тип факту: для логічних — вибір true/false, для чисел — числове поле, для текстових — поле з підказками.

## Впевненість правила (CF)

[CF](reference.md) — число від 0 до 1: наскільки можна довіряти висновку правила.

- Для **проміжних** правил залиште 1,0: порогові критерії вважаються точними.
- Для **діагностичних** правил: діагноз із двома й більше умовами — **0,9**, однофакторний («спостереження», ранній сигнал) — **0,6**.

Якщо один діагноз підтверджують кілька незалежних правил, їхні впевненості **комбінуються**:

`CF = CF₁ + CF₂ × (1 − CF₁)`

Два правила по 0,6 разом дають 0,84, три — 0,94. Незалежні підтвердження підвищують упевненість, але вона ніколи не перевищує 1.

Упевненість діагнозу визначає, як він [показується](diagnostics.md).

## Факти

Вкладка **Факти** показує всі факти бази знань. Форма факту:

| Поле | Значення |
|---|---|
| Назва | Унікальна назва; саме її обирають в умовах правил |
| Вид | raw — вхідний показник, derived — проміжний стан |
| Тип | number, bool або enum |
| Одиниця | Наприклад %, ms, °C |
| Значення за замовчуванням | Необовʼязково |

Новий факт зʼявляється у списках після збереження; на сторінці «Діагностика» — після її перезавантаження. Як створити факт крок за кроком: [Як додати новий факт](howto.md).

## Вхідний показник і проміжний стан

| Вид | Звідки береться значення | Де використовується |
|---|---|---|
| **raw** (вхідний показник) | Його вводить користувач або надсилає агент моніторингу | В умовах правил; на сторінці «Діагностика» |
| **derived** (проміжний стан) | Його виводить правило | В умовах правил наступних шарів; у висновках |

Проміжні стани не можна вводити на сторінці «Діагностика» — їх обчислює система. Терміни: [raw](reference.md), [derived](reference.md).

## Значення за замовчуванням

Для проміжного стану можна вказати значення, яке він отримує **до початку виводу**, якщо жодне правило не встановить інше. Зазвичай це «норма».

Це зручно для двійкових станів: достатньо одного правила «ЯКЩО температура > 85 ТО тепловий_стан = перегрів», а протилежне правило «ЯКЩО ≤ 85 ТО норма» не потрібне.

Щоб задати значення, відкрийте факт і поставте прапорець **значення за замовчуванням**. Якщо правило пізніше встановить інше значення — воно замінить типове без конфлікту.

Значення за замовчуванням не зʼявляється у трасуванні: пояснювати, чому все гаразд, не потрібно — пояснюються лише відхилення.

## Довідник діагнозів

Діагноз описується один раз у довіднику, а діагностичні правила лише посилаються на нього. Тому критичність не може розійтися між правилами.

| Поле | Значення |
|---|---|
| Код | Технічний ідентифікатор, наприклад `memory_leak_critical` |
| Людська назва | Те, що бачить оператор у картці |
| Критичність | 1–4; впливає на [рівень SEV](diagnostics.md) |
| Опис | Що означає діагноз |
| Рекомендація | Що робити оператору |

Видалення діагнозу не перевіряє, чи є правила з його кодом — для цього служить Перевірка бази знань.

## Перевірка бази знань

Кнопка **Перевірити базу знань** (внизу редактора) або пункт меню **База знань › Перевірити базу знань** аналізує правила без запуску діагностики й показує список проблем:

| Ознака | Що означає |
|---|---|
| unknown_facts_in_conditions, unknown_facts_in_conclusions | Правило посилається на факт, якого немає |
| unknown_diagnosis_codes | Діагностичне правило посилається на діагноз, якого немає в довіднику |
| duplicate_rule_ids | Два правила мають один ідентифікатор |
| unreachable_facts | Проміжний факт використовується, але жодне правило його не виводить |
| rules_without_conditions | Правило без умов |
| bad_operators, bad_rule_types | Недопустимий оператор або тип правила |

`total_problems: 0` означає, що база знань справна.
